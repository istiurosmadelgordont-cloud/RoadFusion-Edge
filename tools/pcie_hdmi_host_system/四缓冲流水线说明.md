# 四缓冲取帧流水线

底层驱动原本已扫描四个 DMA 缓冲区。本次将 GUI 的串行读帧/转换拆为独立采集线程和处理线程，处理图像时继续取下一帧。设备描述符在整个采集会话保持打开。

FPGA -> 四个 DMA 缓冲区 -> 原驱动检查及复制 -> 采集线程 -> 最多四个原始帧队列 -> 处理线程 -> 最新预览帧 -> Tk 显示。

四帧队列为额外 ARM 普通内存（约 15.8 MiB 原始数据容量），不是重新分配四个 DMA 地址，也不是零拷贝。处理、显示各自可能持有额外帧。队列满时丢最旧的待处理帧；界面显示处理队列丢旧帧计数。这不是 PCIe 链路丢帧统计。读取 FPS 按已处理帧携带的采集序号估算，存在队列延迟，不是 FPGA 源帧率。

部署：复制 host.py、frames.py、capture_pipeline.py，并保留上版 preview_queue.py。关闭原窗口重新 ./run.sh 即可。驱动没有改动，无需重编或重新上电。--preview-step 3 可进一步降低预览开销。

没有改动 FPGA，不发 CLEAR，仍只首次下发四个 DMA 地址。原协议没有写入开始失效标志/读写所有权交接，不能保证无撕裂或无丢帧。真正让四个 DMA 缓冲区分别处于写入、就绪、读取、空闲状态，需要 FPGA 与 ARM 共同增加握手协议。

验证：新增五项流水线/生命周期测试及原有五项图像测试通过，Python 语法检查通过。ARM 实际帧率、CPU 占用、动态视频正确性仍需硬件实测。
