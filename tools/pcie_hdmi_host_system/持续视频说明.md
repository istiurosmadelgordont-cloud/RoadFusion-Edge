# 持续视频接收模式（2026-09-15）

本说明替代 README 中逐次 CLEAR、停止 DMA、连续快照的旧描述。

- 第一次读取时只向 BAR1 + DMA_CMD_L_ADDR（0x110）顺序写入四个 32 位 DMA 地址；此后读取不重发地址，不发 CLEAR（0x130），不清空 DMA 缓冲区。
- PCI 配置空间的 Memory/Bus Master 设置仍然需要；这些不是 BAR 命令写入。
- FPGA 持续轮转四个缓冲区。应用每次 read 返回一帧 RGB565_LE（1920×1080），跳过上次已交付的相同缓冲区标记。允许丢帧；8 位标记回绕可能使某帧被跳过，不能据此精确计数。
- “连续预览”持续读帧；“停止”或关闭窗口只停止应用读帧，FPGA 保持发送。首次采集后驱动固定驻留，普通 rmmod 会提示使用中，以免 FPGA 继续写已释放内存。不要强制卸载、热拔插或运行时更换 FPGA 程序。
- 更换驱动/FPGA、重新下发地址时，需要双方复位。关闭 ARM 和 FPGA，先启动并配置 FPGA，再启动 ARM。FPGA 必须清除旧地址配置状态，再接收新的四个地址。
- 帧复制前后检查完成标记，只能排除部分覆盖。当前 FPGA 不在覆盖开始时失效标记，也无缓冲区交接协议，因此动态视频仍可能撕裂。这是连续传输联调版本，不保证每帧完整、不丢帧或实时帧率。
- demo 是软件彩条；换真实视频时取消标准彩条校验。图像尺寸/像素格式变化仍需双方同步修改。

## 更新与运行

把 driver/pcie_hdmi_host.c 和 host.py 复制到 ARM 对应目录。完成上述双方断电、FPGA 先启动的流程后，在 ARM 桌面终端执行：

```sh
cd /home/cat/PCIE/pcie_hdmi_host_system
sudo make -C driver clean
./run.sh
```

选择 hardware，点击连续预览。首次读取内核日志应出现四条 stream address 和一条 stream started；后续帧不再重复这些启动日志。

```sh
sudo dmesg | grep pcie_hdmi_host | tail -n 30
```

首次地址下发后 FPGA 若未开始送帧，读取 5 秒超时，驱动不会自动重发四个地址。检查 FPGA 复位及配置状态。

本次仅做源码检查及 Python 语法检查；需在 ARM 上编译内核模块并做连续动态视频实测。
