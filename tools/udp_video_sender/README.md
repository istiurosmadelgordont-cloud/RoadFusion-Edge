# Windows FPGA 视频 / 图片上位机

将本地视频、图片或彩条转换为大端 RGB565，经 UDP 发到板卡一。用于道路素材、四路采集和图像处理演示。**本地预览/发送计数不代表 FPGA 已确认收到。** 系统连接见 [双板 FPGA 说明](../../fpga/dual_board/README.md)，识别程序见 [board_v10](https://github.com/istiurosmadelgordont-cloud/RoadFusion-Edge/blob/a6ab14ee72b9bc163f0428a35f9c44413b2e2eaa/board_v10/CURRENT.md)。

## 快速启动

1. 安装 Python 3.10 或以上，完整保留本目录文件。
2. PC 千兆网卡连接板卡一对应以太网口，在 Windows 中为该网卡配置与目标同网段、且不相同的本机 IPv4。
3. 按下方步骤登记该网卡的目标静态邻居。
4. 双击 [start.cmd](start.cmd)。首次创建 `.venv` 并按 [requirements.txt](requirements.txt) 安装 OpenCV/NumPy，需要能访问包源。
5. 先发送彩条验证，再选视频/图片；核对本机 IP、目标 IP/MAC、输出尺寸，点击开始。

## 两路目标参数

| 板卡一接口 | 目标 IPv4 | 目标 MAC | UDP 端口 | 四宫格位置 |
| --- | --- | --- | --- | --- |
| 以太网0 | `192.168.1.10` | `A0-B1-C2-D3-E4-E4` | `1234` | 左下 |
| 以太网1 | `192.168.1.11` | `A0-B1-C2-D3-E1-E1` | `1234` | 右上 |

当前 FPGA 对这两路按 **960×540 RGB565** 接收。应用可输入其他分辨率，但更改发送输出尺寸不会修改 FPGA 的像素计数和 DDR 配置。双路发送需开两个窗口，各自使用一组目标。

在本目录打开**管理员 PowerShell**，示例本机地址 `192.168.1.102` 必须已经配置到所选网卡：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\configure_network.ps1 -LocalIP 192.168.1.102 -TargetIP 192.168.1.10 -TargetMAC A0-B1-C2-D3-E4-E4

# 第二路；本机 IP 按实际连接和网卡配置选择
powershell -NoProfile -ExecutionPolicy Bypass -File .\configure_network.ps1 -LocalIP 192.168.1.102 -TargetIP 192.168.1.11 -TargetMAC A0-B1-C2-D3-E1-E1
```

[configure_network.ps1](configure_network.ps1) 只修改所选网卡对应目标的静态邻居映射，不设置网卡 IP。当前 FPGA 无 ARP 应答；发送前会核对永久映射，不匹配时显示配置命令并停止。双网卡使用同一子网时还须核对路由，绑定源 IP 和静态 ARP 不替代路由配置。更新程序或网络设置后关闭旧窗口再打开；采集期间不向旧接收器混发 ping 等报文。

## 界面参数

| 参数 | 当前默认值 / 行为 |
| --- | --- |
| 输入尺寸 | 原始尺寸；可手填，输入处理不修改原文件 |
| 输入采样 FPS | 初始 30，选视频后带入原生帧率；图片不使用该值 |
| 输出尺寸 | `960x540`，当前 FPGA 起始设置 |
| 发送 FPS | `10`，目标值，实际速度显示在界面 |
| 速率上限 | `120 Mbps`，允许 1–950，不是硬件吞吐保证 |
| 像素负载 | `256 B`，允许 4–1472 且为 4 的整数倍 |
| 最小包间隔 | `20 μs`，与速率计算间隔取较大值 |
| VS 消隐 | `2 ms`，帧头与尺寸包之间；允许 0.01–1000 ms |
| 缩放方式 | 等比留黑，可选居中裁剪或拉伸填满 |

静态图片可单帧或循环发送，视频可播放至结束或循环。参数在开始时固定，修改后停止并重启发送。正常停止/关闭会完成当前帧，避免半帧停下。

原视频 30 FPS、采样 30、发送 10 时选原帧 0、3、6…；采样 10、发送 30 时重复每个采样帧三次。程序不做运动插帧；跟不上时慢放，不突发补发追赶。发送期间最多预取下一帧，保持单线程按序发完整帧。

## UDP 线缆协议

每帧顺序：

```text
包 1：F0 5A A5 0F                  帧头，4 字节
       等待设置的 VS 消隐
包 2：W高 W低 H高 H低              分辨率，4 字节
后续：恰好 W × H × 2 字节 RGB565    从左到右、从上到下，大端
```

960×540 的尺寸包是 `03 C0 02 1C`，像素 1,036,800 字节；默认 256 B 分包时为 4,050 个像素包，加两个控制包。红/绿/蓝像素分别为 `F8 00`、`07 E0`、`00 1F`。无额外行头、序号、帧尾或填充；Windows/网卡生成 Ethernet/IPv4/UDP 头，发送器禁止 IP 分片。

软件尺寸范围 1–65535，但受内存和解码限制。若 W×H 为奇数，末包是 4n+2 字节，接收器须仅输出最后一个有效像素；旧接收器不支持此边界，不能将任意尺寸直接用于当前 FPGA。

协议无确认、重传和序号；发送错误后停止，不自动补发。默认帧末另等 2 ms。纯像素带宽为 `W×H×16×FPS/1000000` Mbps，另有协议与等待开销，例如 960×540、30 FPS 仅像素就约 248.8 Mbps，120 Mbps 速率设置不能保证发送到 30 FPS。

## 问题排查

| 现象 | 优先检查 |
| --- | --- |
| 启动后报依赖错误 | Python、首次联网安装、`.venv` 与完整目录是否一致 |
| 本机 IP 不可选/同网段检查失败 | 该 IPv4 是否实际配置到连接 FPGA 的网卡，子网与路由是否正确 |
| 开始前提示邻居不匹配 | 用管理员终端执行与当前本机 IP、目标 IP/MAC 一致的脚本 |
| 预览有图但 FPGA 黑屏 | 彩条是否正常、目标端口/映射、输出 960×540、DDR 初始化、FIFO/接收状态 |
| 实际帧率偏低 | 界面的等待画面、解码/转换和发包耗时；速率/包间隔/网卡，不只看目标 FPS |
| 图像撕裂或缺帧 | 恢复默认分包/间隔并观察 FPGA FIFO；必要时正常停止、复位接收端后重启 |

短间隔使用高精度等待，可能提高发送线程单核 CPU 占用。提高软件限速不保证 FPGA 接收或 DDR 能力同步提高。
