## YOLO 红绿灯框闪烁

父灯组按采集时间 650ms 过期可能隐藏仍可显示的子灯；UFLD 可插入 YOLO 定位与 MO 分类之间，导致整组超过 500ms 接收时限被丢弃。

修复把 YOLO＋MO 作为一次 NPU 观测，使用同线程可嵌套的互斥锁，其他上下文仍串行。等待 NPU 后再取真实最新输入，未改写采集时间。父子框统一限制为接收后最多 650ms、原始采集后最多 1000ms；暂存灯态不作为新观测或放行证据。

延迟父子灯组新增回归在旧代码上因 `during_gap.size()==2` 断言失败，修复后通过；覆盖颜色替换、连续漏检、过期清除、组内互斥和等待后取最新帧。原灯组绑定、HSV、9 组红绿未知/方向组合、测试二报警/取消/虚线规则及中心车道显示均通过。渲染检查使用板端实际字体 `wqy-zenhei.ttc`。

| 约 15.5 秒窗口 | YOLO 结果数 | YOLO 过期丢弃 | 车道过期丢弃 | NPU | 程序 CPU（四核合计最高 400%） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧版，车道开 | 45 | 5 | 15 | 57–87% | 222.4% |
| 修复，车道开 | 48 | 0 | 0 | 74–80% | 217.7% |
| 修复，车道关 | 80 | 0 | 0 | 47–63% | 213.2% |

三组开关窗口共 581 个逐帧记录，972 个有真实灯态观测且仍在时限内的视图帧中，未出现可见灯数少于当前观测灯数或被清空。源画面与测试时间不同，不是同帧准确率或完整性能基准。模型真实漏检仍按原规则处理，不能声称所有闪烁均已消除。最终关闭逐帧调试，保留车道开启，未替换模型。

## 复现回归

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target perception_regression npu_executor_regression input_mode_regression -- -j1
mkdir -p output
./build/perception_regression
./build/npu_executor_regression
./build/input_mode_regression output/controls.png /usr/share/fonts/truetype/wqy/wqy-zenhei.ttc
```

`--dump-detections` 可临时启用 `TRACK_FRAME`，记录采集/接收年龄及各视图观测灯数、显示灯数，正常演示不需要。

续训第 8 至 16 轮，最佳教师 KL 略有改善。96 张同输入 NPU 隔离测试：原车道 INT8 均值 134.8ms、续训 QAT 199.3ms；相对 FP32 共有本车道点横向差为 0.972px、1.932px（640px 视图）。候选未优于当前模型，未设为默认；PC 用户素材与真实 INT8 核验见 [QAT 记录](../../training/UFLDV2_QAT.md)。
