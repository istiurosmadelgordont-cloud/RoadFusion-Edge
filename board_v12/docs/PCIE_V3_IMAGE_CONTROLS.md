# board_v10：新版 board_v9 + pcie_v3 + FPGA 图像处理窗口

本版以 2026-10-23 提供的新版 board_v9 为基础，保留其导航、测试四、车道线、NPU 调度与识别/报警逻辑。
原始 board_v9 未被覆盖。driver/ 以工作区 pcie_v3 驱动 8.0 为基线，现升级为兼容原协议的 8.1；
高精度等待和锁优化见 [驱动性能说明](DRIVER_PERFORMANCE.md)。工作区 pcie_v3 本身未改。

## 编译和启动

把整个 board_v10 复制到鲁班猫；在板子的 board_v10 根目录编译。不要沿用旧目录的 CMakeCache。
模型继续放 models/ 或 ../models/，YOLO 和 mo_fp16_baseline.rknn 必须位于同一个目录。

```sh
# 首次替换驱动时需要编译，KERNEL_DIR 可按板子内核源码位置覆盖
make -C driver
# 先关闭所有正在使用设备的旧程序，再卸载旧模块；卸载失败时先处理占用，不强行卸载
sudo rmmod my_pciedriver
sudo insmod driver/my_pciedriver.ko
sudo chown "$(id -un):$(id -gn)" /dev/fpga_frame_*

# 编译上位机，不需要额外安装 Qt 开发包
sh scripts/build.sh
sh scripts/run_pcie.sh
```

如果驱动尚未加载，省略 rmmod。pcie_v3 8.0 仍可运行本应用；要启用 8.1 性能改动需退出采集后重新加载模块。
外置内核目录示例：make -C driver KERNEL_DIR=/实际位置/kernel。
START/STOP、视频 ABI 2、1920×1080 RGB565、四 DMA 槽以及默认 read 采集保持不变。
run_pcie.sh 仍只启动应用，不自动更换已加载的驱动。

## 参数窗口

主界面右上角“图像处理”向下展开十套预设；选中后更新按钮上的预设名称，点击旁边的“应用设置”才发送。
列表底部的“详细处理...”打开原来的独立参数窗口；不暂停视频接收。车道线开关保持在左上角。
“恢复默认”把同一份草稿恢复到全旁路，仍须点击“应用设置”后才作用于 FPGA。
快捷预设与详细窗口共享草稿，在详细窗口调整后也可以从主界面应用；主界面按钮下方显示提交/回执提示。
再次点击下拉按钮、点击菜单外或按 Esc 可收起列表；点击菜单外不会同时触发下方的驾驶模拟按钮。
点击开关启用/关闭对应算法；数值用 +/- 微调，或点击横条设置。降噪 sigma 仅取 16/32/48。
内置与 pcie_v3 查看器相同的十个预设、十一个开关、十三个数值参数，包括去雾、Gamma、CLAHE、
高光保护、亮度降噪、透射率滤波、天空/阴影保护，以及旧暗光增强和高光压制。

- 修改控件不会自动发送；“应用当前参数”才提交五个参数字。
- “恢复默认（仅编辑）”只更新窗口草稿；“恢复旁路并应用”会实际提交旁路预设。
- 参数作用于整张 FPGA 输出图像，识别模型随后读取处理后的画面；不修改识别/报警程序规则。
- 窗口不是 FPGA 参数读回：新开程序默认显示旁路草稿，不据此声称硬件当前处于旁路。
- 关闭窗口保留草稿，也不撤销已经提交的参数；图像配置并不会因视频 STOP 自动清除。
- 文件回放可以浏览参数，但禁止向 FPGA 提交。

窗口底部显示控制状态和最近日志。参数由同一采集 fd 上的独立线程提交，GUI 不等待 ioctl。
驱动能力查询仅表示驱动支持，不能证明 FPGA 位流版本匹配。

## 回执与恢复

驱动 8.0：采集 START 之前登记独立回执 DMA 邮箱；应用后等待 RECEIVED、再等待 APPLIED。
SUBMIT 成功只表示参数写操作已发出；只有匹配 cookie 和参数的双阶段回执才显示“已生效”。
APPLIED 也不表示主机窗口已经显示了对应的视频帧。

3 秒超时后保留在途事务，不自动重发、不允许覆盖，继续监听迟到回执。
如一直超时，退出采集程序使 STOP 排空，再重新运行；同时核对支持 IMAGE_ACK_20261017 的 FPGA 位流。
不要把缺少回执当作参数一定没有生效。
驱动 7.0 仅支持单向提交时会明确显示“不能确认硬件生效”；无参数能力的旧驱动仅禁用调参，不阻断视频。

## 检查范围

新增 image_control_regression、pcie_capture_regression；原有导航、测试四、车道、跟踪和红绿灯按钮回归保留。
已在鲁班猫原生环境完成本版 ARM 构建和 image_control_regression，另用回放主界面实际点击验证下拉选择预设、“详细处理”、参数窗口关闭与重新打开，以及窗口完整位于屏幕内；测试不提交 FPGA 参数，未验证真实回执与图像处理效果。
快捷菜单增加了预设选择、共享草稿、显式应用、恢复默认、回放/忙状态门禁、点击隔离及底图恢复检查。
修复 OpenCV 3.2 GTK 的窗口兼容问题：该后端的 WND_PROP_VISIBLE 返回 -1 表示不支持，不能据此关闭窗口；改用 cvGetWindowHandle 检查窗口是否存在。设置初始窗口位置，避免日志区超出 1080p 屏幕。
原模型文件不随本次源码复制；模型清单仍见 config/model_manifest.json。
