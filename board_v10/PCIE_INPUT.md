当前新增图像处理窗口及回执控制，详见 [操作说明](docs/PCIE_V3_IMAGE_CONTROLS.md)。以下保留原视频及按钮逻辑说明。

# board_v9：PCIe 用途车道与方向按钮切换

实时输入继续使用 pcie_v3 ABI 2 和 read，默认不限显示帧率。
本版修改上位机的车道、选灯和按钮逻辑；随附内核驱动已同步为 pcie_v3 8.0，图像调参见 docs/PCIE_V3_IMAGE_CONTROLS.md。
文件回放和 PCIe 实时图像使用同一套新规则。

## 三排控件

1. 用途车道：左转车道 / 直行车道 / 右转车道，单击选择并保持。
2. 行驶方向：左转 / 直行 / 右转，第一次单击开始模拟行驶，再点同一个按钮停车。
   行驶中点击另一方向，切换方向并继续行驶。松开鼠标不会停车。
3. 车辆行驶 / 车辆停止：只显示状态，不接受点击命令。

车道和方向独立选择，切方向不会切换车道或改选其他方向的灯。
正在行驶的方向按钮高亮，停车后取消方向按钮高亮；用途车道仍保持选中。
1/2/3 对应方向按钮，4/5/6 选择用途车道；H 叠加开关，V 环视放大，Q/Esc 退出。
没有自动或强制行驶模式，也不使用 A/G/S/空格控制车辆状态。

## 控制灯与报警

| 用途车道 | 控制灯 | 内部类别（红 / 绿） |
| --- | --- | --- |
| 左转车道 | 左转箭头 | 8 / 12 |
| 直行车道 | 优先直行箭头，无箭头时圆灯 | 10 / 14；7 / 11 |
| 右转车道 | 右转箭头 | 9 / 13 |

仅使用前视画面的新检测结果，不读取 signal_demo.txt，不依赖场景 ROI 或方向绑定。
左/右箭头缺失时不使用圆灯代替。直行同时支持直行箭头和圆灯，箭头优先。
直行箭头短时漏检 0.8 秒内不立即切换到圆灯，等待恢复；超过窗口再对圆灯重新确认。
多个圆灯优先选前视画面水平中间的目标；同等位置考虑置信度，保留少量位置余量防抖。
不同灯不会共用确认次数，目标或车道切换、颜色冲突都会撤销原判断。

红灯至少两次新观测且跨度达到 0.2 秒；绿灯至少三次且跨度达到 0.6 秒。
两次有效观测间隔超过 0.8 秒重新确认。重复显示、追踪预测不增加票数。
缺灯、换色、冲突或 0.8 秒没有新证据时，显示等待确认，不把未知灯当成红灯。
检测到候选控制灯即可按原样式描边，确认后加粗，避免把未确认误认为未选灯。

左转车道只允许左转，直行车道只允许直行，右转车道只允许右转。
用途车道仍决定选哪盏灯，方向按钮不会替换该车道的控制灯。

| 当前控制灯 | 正在模拟行驶的方向 | 报警 |
| --- | --- | --- |
| 确认红灯 | 任意方向 | 闯红灯 |
| 确认绿灯 | 与用途车道一致 | 不报警 |
| 确认绿灯 | 与用途车道不符 | 违规操作 |
| 未知/未确认 | 与用途车道一致 | 等待确认，不伪报闯红灯 |
| 未知/未确认 | 与用途车道不符 | 违规操作（车道用途已由用户选择确定） |
| 任意灯态 | 已停止 | 不产生上述行驶报警 |

红灯时若方向也违规，优先显示“闯红灯”，不被“违规操作”覆盖。
界面小叠加、顶部预警、侧栏、状态日志同时使用当前报警类型。
再次点击当前方向按钮停车，即解除行驶报警；普通红灯停车提示仍可保留。
确认绿灯且方向匹配时才显示原绿色行驶箭头；绿灯不会自动启动车辆。
本次没有新增硬件蜂鸣器、LED 或真实车辆控制。

## PCIe 输入

FPGA -> pcie_v3 驱动 -> read 完整 RGB565 帧 -> BGR -> 共用检测/选灯/预警/绘制。
图像仍为 1920x1080、stride 3840、4147200 字节、四个 DMA 槽。
四路位置：左上前视、右上后视、左下左视、右下右视。
保留短读补齐、独立采集线程、只发布最新完整帧和 START/STOP 退出流程。
界面每次最多等待新帧 16ms；断流时显示最后一帧（首帧前为黑图），仍处理方向切换、停车与退出。
旧画面不重复送入推理；灯态按单调时钟过期。read/DMA/寄存器协议没有改变。
默认 --display-fps 0，不额外限速；实际速度仍取决于硬件、识别和绘制耗时。

PCIe 的 --scene 现在只用于可选 AVM 标定等素材元数据，不用于选择控制灯，
不需要为了右转或另一组测试视频切换 signal_demo.txt。
回放仍用 --scene 选择视频文件，按原视频时间轴播放。
中心圆灯选择是本演示规则，不能自动推断真实路口道路归属。

## 编译和启动

将更新后的整个 board_v9 同步到板子。YOLO 和 mo_fp16_baseline.rknn 放同一模型目录，
脚本优先查找 models/，其次 ../models/；也可设置 MODEL / UFLD_MODEL。

已经加载相同 pcie_v3 8.0 模块时不需重编驱动。首次使用：

```sh
make -C driver
sudo insmod driver/my_pciedriver.ko
sudo chown "$(id -un):$(id -gn)" /dev/fpga_frame_*
```

内核构建目录不在默认位置时指定 make -C driver KERNEL_DIR=/实际路径/kernel。
本次必须重新编译上位机，再从图形桌面终端启动：

```sh
cmake -S . -B build
cmake --build build --target adas_four_view -- -j2
sh scripts/run_pcie.sh
```

多设备使用 PCIE_DEVICE=/dev/fpga_frame_<BDF>；--demo-lane left|straight|right 可选初始车道，默认直行。
原 --demo-direction 参数仅作为初始车道参数的兼容别名，不会启动持续行驶。
GLES 和 --opencv 两种显示均支持单击方向按钮切换行驶/停车。原回放入口 sh scripts/run_four_view.sh。
脚本只启动已编译程序，不会自动编译或加载驱动。

```sh
cmake --build build --target input_mode_regression -- -j2
./build/input_mode_regression
```

检查不访问 PCIe 或 NPU，不能替代板端对实际识别结果、图形事件和帧率的联调。
