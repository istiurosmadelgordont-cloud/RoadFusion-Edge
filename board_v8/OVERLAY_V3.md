这是可继续开发的阶段版本，尚未完成参考效果图的整体验收。导航、真实车速和挡位展示不在本轮范围内。

- RK3568 板端 `adas_four_view` 编译通过，`perception_regression` 与 `overlay_regression` 通过。
- 已检查真实 NVIDIA 四路回放，以及明确标记为模拟风险输入的 FCW/RCW、BSD/LCA 画面。
- 在 `66b5fa4b_30fps` 单次完整回放中，右侧 BSD 能触发，并在约第 16 秒解除，之后到第 19 秒保持解除。实机模拟右转向输入能将右侧提示从黄色 BSD 升为红色 LCA；截图时显示约 22 FPS，此值不代表所有场景的性能。

前视画面按“当前信号灯、FCW 目标、车道边界、视觉车道中心区域、其他检测目标”的顺序表达重点。普通车辆保留细青蓝框，行人与骑行目标保留低亮度紫框，减少多辆车的文字重叠；当前信号灯在框旁标明 `CURRENT`，选中的前车显示独立风险卡。

## 车道视觉区域

- 在左右边界可见时，按实测车道宽度绘制透视淡出的半透明本车道；几何完整时使用浅绿色和沿实测中心排列的短箭头，部分几何改用低亮度灰色，车道身份不确定时隐藏。它由当前车道几何生成，是视觉引导示意，**不是车辆轨迹预测或控制路径**；没有车辆航向角、标定和运动模型时不外推未来轨迹。
- UFLD V1/V2 的 4 个槽位均保留。V2 遵循官方混合解码：第 1/2 槽使用 `loc_row/exist_row`，第 0/3 槽使用 `loc_col/exist_col`。外侧列锚点支持率须大于 1/4，再经图像范围、左右顺序、纵向支持跨度和相对宽度校验后组成左右邻接候选区域；不向观测点之外延伸。此前把四槽都用行分支解码的做法已修正。
- 邻接几何与变道许可分开：外侧几何有效时可绘制较淡的候选色带，分隔线识别为虚线时增强颜色。左邻候选为橙色，右邻候选为紫色；这些颜色表示相对位置，不表示危险等级或允许变道。外侧线的实/虚/未知单独记录，未知绘制点线。仅凭 UFLD 外侧边界仍不能完全区分车道与路肩，当前结果不宣称完整车道拓扑或跨帧 Lane ID。
- 正常本车道区域为浅绿色，已知 TLC 小于 2.5 秒时只将靠近风险一侧着黄，小于 1.5 秒时着橙；另一侧仍保持原色。部分几何不参与 TLC 风险着色。
- 只有 LDW 确认越线时，越线侧边界和相邻区域变红；另一侧边界保持自身状态。实线、虚线和未知线型继续分别绘制。
- 中心区域向远处逐渐淡出；TLC 预警显示对应方向箭头。缺少航向和标定时不把中心区域宣称为预测轨迹。

## 前车风险卡

- 目标至少经过两次观测确认后才显示 FCW 卡片和高亮框。卡片优先放在目标上方，避免遮住近处道路和红色告警边界；没有足够空间时再放到目标下方。它显示 Track ID、单目估计距离、接近或远离速度和 TTC。估计值加 `~`，TTC 保留一位小数；没有可信 TTC 时显示 `--` 且风险等级保持灰色，除非估计器已经因距离触发告警。
- 风险条按 TTC 分为正常（≥4 秒）、注意（3–4 秒）、警告（1.5–3 秒）和危险（<1.5 秒）。风险估计器若因近距离触发告警，卡片至少显示警告级；目标尚未连续确认时显示灰色。
- 已确认且达到警告级的 FCW/RCW 目标框外增加局部柔光，普通车辆不发光。柔光只依附已匹配目标框，不根据单目框大小虚构道路上的危险范围。
- 距离来自目标框高度的单目估计，受目标类别尺寸和检测框误差影响，只作演示提示。

本版沿用 YOLO、UFLD 模型，补充跟踪显示所需的运动有效性信息，并调整 BSD 确认与过期处理；不增加显示帧率上限。视频素材与截图仅保留在本地验证目录。

## 四路 HUD

- 四路等大，右侧周边感知使用四方向雷达环。前后已确认风险按 TTC 等级点亮对应扇区，左右盲区只在侧视数据新鲜时点亮；有转向意图且盲区被占用时升为红色。雷达环只表达风险来源，不将像素坐标映射成物理距离。普通车辆框用细青蓝线，行人/骑行目标用低亮度紫线，FPS/NPU 降低字号和亮度。
- 后视显示 RCW 目标卡和接近箭头。箭头长度随估计接近速度增长，它是接近提示，不代表标定后的世界运动方向；不画固定道路梯形。
- 侧视空盲区与过期数据不再绘制占满画面的固定梯形；分别标记 `BSD CLEAR` 与 `BSD UNAVAILABLE`。目标被确认占用时，在对应检测框底部绘制局部黄色接地区域；转向意图与占用同时存在时变红并标记 `LCA BLOCKED`。该区域只随图像中的目标位置变化，不宣称经过标定的盲区边界、真实距离或运动轨迹。侧向占用须有连续两次有效观测，换车或跟踪 ID 切换不会把区域确认计数清零；超过 1.8 秒没有四路检测时隐藏侧向告警，超过 2.5 秒时清空确认状态。
- 前视变道卡显示方向、READY/CHECK/BLOCKED/CHANGING/DONE、线型、盲区状态和状态机原因；模拟输入明确标注 DEMO。READY 是现有演示状态机提示。
- 顶部统一告警由 WarningManager 的最高优先级驱动。普通盲区关注为黄橙，碰撞与偏离告警更醒目。
- 路口必须具有有效方向意图才选灯；转向灯关闭不自动等于直行。当前匹配灯使用白色外框，其他灯保持低亮度。换方向重新确认，方向未知不回退到普通灯色的 GO。明确直行输入可通过 `VehicleState.route_valid/route` 接入。
- 四路等大画面的外框根据各自风险状态显示灰、黄、橙、红；橙/红状态轻微呼吸。正常状态保持静止，告警解除后立即恢复暗色边框。
- 顶部风险条仅在注意或告警时出现；有明确 FCW/RCW 告警时显示相应 TTC。平时恢复系统标题。前视 FCW 危险时，已确认车道的中心区域同步转为淡红；目标框加粗。右侧雷达环同步点亮对应方向。
- 方向扇区只表示前、后、左、右告警来源，不代表车辆世界坐标。共享 NPU 下感知过期时，侧向扇区和边框不继续保持旧告警。

## 回归检查

`overlay_regression` 检查未确认目标不显示风险卡、已确认目标的正常/危险颜色、右侧 LDW 不将左边界染红，以及邻接候选在车道身份不确定或外侧线支持不足时隐藏。`ufld_decode_regression` 用互相矛盾的行/列输出检查分支选择、坐标变换、支持率分母和缺失分支行为。板端执行：

```sh
cmake --build build --target overlay_regression -- -j2
./build/overlay_regression
cmake --build build --target ufld_decode_regression -- -j2
./build/ufld_decode_regression
```

真实四视角回放用于检查卡片遮挡与显示性能；合成画面用于覆盖真实片段未稳定触发的风险等级。这些检查不代表距离、TTC 或轨迹预测的准确率验证。

2026-09-28 核对官方实现后修正了 V2 外侧槽位错误使用行分支的问题。PC 使用本仓库 `ufldv2_culane_res18_1600x320.onnx` 对真实 `66b5fa4b` 前视第 262 帧做混合解码；外侧两条线分别得到 33/81、28/81 个列锚点。本地检查图为 `board_v8/output/highway_front_262_hybrid_slots.jpg` 和 `highway_front_262_hybrid_preview.jpg`。此前只使用行输出的预览图不作为外侧解码验收依据。

同日在 RK3568 板端用 `ufldv2_culane_res18_1600x320_int8.rknn` 和真实四路场景 `66b5fa4b_30fps` 重新回放 300 帧（对应素材目录 `11_side_vehicle_bsd`）。`adas_four_view`、`ufld_decode_regression`、`overlay_regression` 编译通过，两项回归通过；四路回放退出码 0，平均约 15.4 FPS。第 270 帧日志记录四槽支持率为 0.383/0.472/0.472/0.333，左右邻接 polygon 均生成，截图为 `board_v8/output/board_hybrid_real_66b5_frame270.png`。显示层允许两侧本车道覆盖率都达到 0.45 且车道身份确定的密集有效拟合显示绿色，安全逻辑仍保留原严格门槛。已启动同场景的板端全屏循环回放；可见 GLES 窗口抽样约 20–23 FPS，与无窗口截图回放的性能不能混用。

当前只验证了前视的混合解码及候选区域；外侧区域仍可能随遮挡和几何校验间歇隐藏，整段视频的稳定三车道效果尚未验收。后视车道在本轮回放中关闭，侧视未使用 UFLD。回放没有验证实时摄像头接入、车道属性准确率、跨帧 Lane ID 或参考效果图所示的四路完整多车道视觉效果。

PC 上可用 `python board_v8/tests/ufld_onnx_preview.py --model models/ufldv2_culane_res18_1600x320.onnx --image FRAME.jpg --output board_v8/output/lane_preview.jpg --raw-output board_v8/output/lane_slots.jpg` 对另一帧复核。这个工具的着色是 C++ 逻辑的近似预览，实际验收仍以板端画面为准。

2026-09-29 针对快速车辆检测框滞后，调整共享 NPU 调度：1600 宽 UFLD 配置中，目标检测服务目标从 700 ms 改为 120 ms，前视车道为 320 ms，并禁止连续两个车道任务绕过目标检测。服务目标不是实际刷新周期；板端同一真实高速片段抽样的目标启动间隔约 403–423 ms，结果交付帧龄约 202–217 ms，可见显示约 18.5–19.5 FPS。日志新增 `object_interval_ms/object_result_ms/object_age_ms`，调度回归覆盖前/后车道共同占用 NPU 时的目标更新间隔。第 270 帧截图为 `board_v8/output/board_yolo_latency_frame270.png`；侧车框仍有少量偏移，尚不能宣称连续视频零滞后。
