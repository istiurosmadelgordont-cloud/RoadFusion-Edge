# ARM RC 四缓冲握手操作指南（协议 v2）

适用：本目录 `source/source/pcie_dma_ctrl.v`，标记 `PCIE_HS_20260919`。默认 1920×1080 RGB565；PCIe MWr32，单包 Payload 64 字节。本文是驱动适配契约，不是声称已在 ARM 板验证完成的现成驱动。

## 1. 与旧版不兼容的地方

- 登记四个地址只完成配置；必须再登记状态区地址、写 START，才能开始。
- 帧尾从“重复 8 位帧号”变为“重复 32 位令牌”；不能用旧版标记解析函数。
- 每块缓冲完成后一直被 FPGA 锁定。RC 用完后向 `0x170` 写回完整令牌，否则四帧后自然停在无空闲状态。
- `0x130` 现在是 STOP(cookie)，不再立即清地址。必须等内存中的停止完成通知，才能安全卸载 DMA 映射。
- `0x1A0` 单独清配置，只在停止状态生效。
- BAR1 仍是写命令接口；本模块没有实现 BAR 读回 Completion、MSI 或用户态 ioctl 接口。不要 `readl(BAR1)` 做 posted-write flush。

## 2. 缓冲布局与所有权

每个图像缓冲最少 `0x3F4840 = 4,147,264` 字节，四块互不重叠，DMA 地址非零且 64 字节对齐，整个范围位于 32 位 DMA 地址空间。分配时可向页大小取整。额外分配一个独立、非零、64 字节对齐的 64 字节状态区，不能与四块图像缓冲重叠。

| 区域 | 偏移 | 大小 | 含义 |
| --- | --- | --- | --- |
| 图像 | `0` | `0x3F4800` | RGB565，共 64,800 个图像包 |
| 完成标记 | `0x3F4800` | 64 字节 | 16 个相同的 LE32 token |
| 独立状态区 | 独立 DMA 地址 | 64 字节 | 16 个相同的 LE32 STOP cookie |

`token = (allocation_sequence << 2) | slot`。slot 为 0～3，sequence 从 1 开始，每次预留缓冲加 1，丢弃的帧也可能消耗序号。因此序号允许跳号，不等于严格连续的成功帧计数。第一次预留 slot 0 的 token 为 `0x00000004`，在 ARM 内存中为字节 `04 00 00 00`，重复 16 次。

FPGA 的状态为 `FREE → WRITING → HELD → FREE`。软件可以把 HELD 再区分成 READY、READING、DISPLAYING；这些是软件内部状态，FPGA 只关心是否已经归还。归还必须同时满足：该槽当前为 HELD，token 完全匹配，sequence 非零。WRITING、重复或旧 token 的归还会被忽略。

当四块都被持有时，FPGA 在下一 VS 跳过整帧，不覆盖任何 HELD 槽。RC 归还一块后，最早从随后的完整帧边界恢复。归还与 VS 恰好同拍时，新空闲位可能下一帧才使用，这是允许的保守行为。

## 3. BAR1 寄存器

以下数值均为逻辑命令值，要求 32 位对齐、1 DW Memory Write、First BE=0xF、Last BE=0。不要把四个地址合并成一条 Length=4 的 TLP。

| 偏移 | 命令值 | 行为 |
| --- | --- | --- |
| `0x110` | 一个图像缓冲的 DMA 地址低 32 位 | 停止时依次登记 slot 0、1、2、3；第四次验证范围不重叠后锁定配置 |
| `0x130` | 非零、此次请求唯一的 cookie | 停止采集、完成已经呈现的 TLP，然后向独立状态区回写 cookie |
| `0x140` | 低 8 位阈值 | 打开高光抑制 |
| `0x150` | 低 8 位阈值 | 打开暗光提升 |
| `0x160` | 0 | 清除两种增强 |
| `0x170` | 帧尾读出的完整 token | 归还该 token 对应的 HELD 槽 |
| `0x180` | 独立状态区 DMA 地址低 32 位 | 四个图像地址配置完成后、停止时登记 |
| `0x190` | 1 | START；等待下一完整 VS 才采集 |
| `0x1A0` | 1 | 停止且发送器空闲时清配置；不重置令牌序号 |

非法命令被忽略，没有错误读回寄存器。联调时用 ILA 查看 `rc_cfg_ep_flag`、`status_addr_valid`、`running`、`buffer_state`、`buffer_token`、`invalid_releases`、`dropped_frames`。

## 4. 字节序必须先验证

RX RTL 执行 `command_value = endian32(axis_master_tdata[31:0])`。例如逻辑 START=1，应在 IP 用户接收口看到 `axis_master_tdata[31:0] = 0x01000000`；逻辑地址 `0x12340000` 对应 `0x00003412`。请按当前 IP 的总线字节映射验证 `writel()` 是否已经产生这个结果，不能额外盲目加一次 bswap。

TX 的完成数据在用户口重复 `endian32(token)`，沿用当前工程的数据字节映射，目标内存约定为 LE32 token。首次上板须同时核对 ILA 和 ARM 内存的 token=4，以及非对称 STOP cookie，例如 `0x12345678`；仅使用全 0、全 1 无法验证字节序。

`rc/handshake_reference.h` 将平台映射放在 `bar_write32` 回调中。该回调接收本文的逻辑值。若首次验证发现内存 DW 映射不同，应修正一致的 IP/驱动适配层，不要在每个调用点随意交换字节。

## 5. 首次启动

1. 枚举、申请设备资源、映射 BAR1；执行 `dma_set_mask_and_coherent(..., DMA_BIT_MASK(32))` 并检查结果，启用 Bus Master。
2. 确保设备处于本次已知复位后的空闲态。驱动重载后若旧 DMA 状态未知，不能直接替换地址或释放旧内存；先完成原会话 STOP，或走平台支持的复位与 DMA 排空流程。
3. 用该 PCIe 设备的 DMA API 分配四块图像缓冲及状态区；提供 `dma_addr_t` 地址，不是 `malloc` 指针、CPU 虚拟地址，也不假设 CPU 物理地址等于 DMA 地址。
4. 推荐首版使用 coherent 分配。清零四个尾标记及状态区；初始化软件持有表、last_token 表。执行必要的 DMA 写屏障。
5. 按顺序写 `0x1A0=1`，四次 `0x110=addr[0..3]`，再写 `0x180=status_addr`。在同一锁/控制线程下顺序提交这些 MMIO 写。
6. 可选但推荐：在启动前发送一次 STOP(cookie)，等待状态区 16 个 DW 都匹配。这样可验证配置、EP→RC DMA 和字节序；测试完成后清状态区并执行写屏障。
7. 写 `0x190=1`，开始轮询图像尾标记。初次启动要等下一个完整 VS；中途写 START 不会从半帧开始。

地址登记失败后先在空闲态清配置，再重新发送全部地址，不能靠猜测当前登记索引补写。64 位地址不能截断；Scatter-Gather 内存也不能仅填第一页地址，当前 RTL 要求整个 DMA/IOVA 范围连续。

## 6. 接收、显示与归还

接收线程只检查软件当前未持有的槽：读取 16 个标记 DW，必须全部一致、非零、slot 正确、sequence 非零，且 token 不等于该槽上次已经接收的值。完成标记可分多笔写入内存，不能看到第一个 DW 改变就立刻判定整条标记完成。

对于 coherent 内存，驱动使用 `READ_ONCE()` 读取标记，完整校验后用 `dma_rmb()` 建立后续像素读取顺序，再把“slot+token+帧地址”交给应用。内存屏障不代替设备完成通知；只有先识别到有效完成标记才允许读像素。对 non-coherent/streaming 映射，还需要正确的 DMA sync/所有权移交，不能只用 volatile 或普通 CPU 原子操作替代。

软件给每个槽维护消费者引用计数。CPU、RGA、NPU、显示队列都要持有自己的引用；全部完成后才可归还。DRM 提交返回不是扫描结束；等待确认旧 framebuffer 已退出扫描的翻页/fence 事件。完成通知或 fence 的接线属于 ARM 驱动/显示实现，本 RTL 不会自动读取它们。

归还顺序：确认最后一个消费者结束 → 在仍拥有缓冲时清零 64 字节尾标记 → 执行 DMA 写屏障/必要 sync → 写 `BAR1+0x170 = 原 token` → 软件标记该槽等待下一帧。从发出 RELEASE 起，软件不得继续读写该槽，也不能再清一次标记。建议同一锁下完成这段顺序。

可以丢弃尚未开始处理的旧 READY 帧并立即归还，以显示最新完整帧。正在使用的帧必须等消费者完成。归还可以乱序，例如 2、0、3、1，不必跟 FPGA 的顺序一致。

## 7. 停止、重启和卸载

1. 停止提交新的显示/推理任务，保持四块 DMA 缓冲和状态区仍然有效。
2. 清零状态区，执行 DMA 写屏障，发送 `0x130 = 本次非零 cookie`。每次使用不同 cookie，不能把旧 ACK 当作新 ACK。
3. 轮询状态区，直到 16 个 LE32 DW 全部等于 cookie；随后执行 DMA 读屏障。这个内存 ACK 排在之前的图像/帧尾 MWr 后面。
4. 等全部已有 CPU/RGA/NPU/显示消费者结束。STOP 只保证 FPGA 停止写，不能替你停止显示硬件读。
5. 同地址重启：清尾标记、更新软件持有状态、屏障后写 START。更换地址：先写 `0x1A0=1`，重新登记四个地址及状态区，再 START。结束使用时才释放 DMA 内存。

STOP 超时应报错并保留 DMA 映射，不能“等固定毫秒数就释放”。若链路故障无法收到 ACK，需由驱动执行平台验证过的禁用/复位/排空恢复流程。普通 BAR 写完成只表示请求提交，不等于 DMA 已排空。

STOP 可以在 Header 或数据背压时等待任意长时间。已对 IP 呈现的 TLP 必须完整结束；如果它已经是帧尾，RC 可能先收到该帧完成，再收到 STOP ACK，这是正常情况。不要要求 STOP 之后一笔旧数据也不能出现。

本设计的 MWr 使用相同 Requester、TC=0，Header 的 Relaxed Ordering/IDO 位为 0；停止/帧尾排序依赖 PCIe IP、桥和 DMA 内存正常遵循该顺序。不要在集成时另行开启松散排序破坏这个约定。

## 8. 异常和寿命

- 不归还：最多收到四帧，之后按帧跳过；这是预期行为。
- PCIe 背压跨帧：完成当前 TLP、丢弃剩余旧帧；未发完成标记的槽可重新使用。
- FIFO full：取消本帧，不再发布新的完成标记。底层 FIFO 的复位/跨域仍需板级验证。
- 令牌 sequence 不在 STOP/START/清配置时归零，防止旧 RELEASE 命中新帧；达到 `0x3fffffff` 后停止分配，需受控复位恢复。按每秒 60 次分配约 207 天，不能依赖自然回绕。
- FPGA 硬复位会重置序号。RC 必须同时结束旧会话、清理消费者与旧命令；不能跨 FPGA 复位重放旧 RELEASE。
- 本改动解决 RC 缓冲覆盖，不解决 DDR 写页避让、增强 RGB 饱和高位、增强参数 CDC 等原工程问题；详见代码说明。

## 9. 上板验收

先不开增强、不接 NPU，按以下顺序测：四帧不归还后停止更新；只归还槽 2 后仅槽 2 更新；旧 token 重放不改变新帧；显示持续持有某槽超过四个输入帧仍不变；背压期间 STOP 待发送排空后 ACK；重复启停及更换 DMA 地址无旧地址写入。最后再接 RGA/DRM/NPU 的异步完成回调。

还需检查 RGB565 字节顺序、每帧像素数、帧尾偏移、实际视频 VS 的极性和消隐长度。成功合成或控制器仿真不等于这些板级条件已验证。
